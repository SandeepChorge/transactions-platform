SPEC transactions-parser-android · dashboards · v1 · 02 Sep 2026

Dashboard build specification

Implementation reference for the reimagined dashboards: every widget, the data it needs, how it looks, how it behaves, plus the tokens, dimensions, icons and strings needed to build it. Numbers in examples are sample data — the widget contracts are the spec.

0 · How to use this document

Three artifacts, in priority order, when implementing a screen:

1
The repo (SandeepChorge/transactions-platform, branch main, path transactions-parser-android) is the source of truth for entities, DAOs, DI, navigation and existing composables. Read it first; do not take field names from this document.
2
Reimagined App.dc.html is the source of truth for layout: it is a live, tappable rendering of every screen and state described here. Open it next to this document.
3
This document is the contract: widget-by-widget behaviour, data requirements, states, tokens and copy — the things a screenshot cannot tell you.
On “can Claude fetch this automatically?”
Yes, with a pointer. In a coding session, give it the repo plus these two files and it can read both directly — the prototype is plain HTML, so tokens, dimensions and copy are machine-readable, not trapped in an image. What it cannot infer is intent: which variant you picked, which dashboards ship in v1, and what a widget should do when data is missing. That is what sections 1–6 below pin down. Keep this file updated as decisions change; it is the handoff, not a snapshot.

3 · Dashboard system

Home is not one screen — it is a set of dashboards, each a stack of widget cards over the same date range. Seven ship; the user controls which are on, their order, and which opens at launch.

Persistence
Per user, in preferences (not the DB): order: List<String>, disabled: Set<String>, default: String. Unknown ids are ignored on read; new dashboards ship enabled and appended.
Navigation
Variant A: horizontal pager over enabled dashboards, dot indicator + “Swipe between dashboards · 2/6”. Variant B: scrollable named tab chips. Variant C: no switching — every enabled dashboard renders as a section of one scroll, in order.
Range
One range applies to every widget on every dashboard, set from the header chip: Today · This week · This month · Last month · Last 3 months · This year. Default: This month. Changing it re-queries; it does not reset the pager position. Range survives process death; it does not persist across app restarts (always reopens on the default).
Gallery sheet
Star to set default, drag to reorder, switch to enable/disable, and “Build a dashboard” to enter the builder. Reached from the header icon button or Settings → Dashboards.
Builder
A checklist of the eight widget types (net spend, daily line, category breakdown, top payees, in vs out, budget progress, recurring due, mapping health) with a live count line; Save writes a user-defined dashboard composed of the checked widgets in list order. Widgets are the unit of composition — this only works if each is built as an independent composable driven by its own query.
Suggested v1 cut: ship pulse, category and mapping — they need no data the parser doesn't already produce. budget needs a new limits table, recurring needs a detection pass, and ledger/payees need reliable credit/debit direction on every row. Confirm each against the repo before committing.

4 · Widget catalogue

Each widget is a self-contained composable: one query in, one card out, no knowledge of which dashboard it sits on. Data lists what it must be given, expressed against the parsed transaction set (transactions joined to payee alias and category, filtered by range) — verify the actual field names in the repo. Empty is mandatory: a fresh install has no statements, and every widget will be seen with zero rows.

W1 · Net spend heropulse
Job
Answer “how much did I spend” in one glance, then explain the change in one sentence.
Data
Sum of debits in range; sum of debits in the immediately preceding equal-length range; the category with the largest absolute increase between them.
Look
Card radius 22, padding 22. Eyebrow “NET SPEND · <range hint>”. Amount mono 700/44, tracking -1. Below: delta in pos/neg colour, 600/14 with ↑ or ↓, followed by muted continuation text on the same baseline.
States
Empty: amount ₹0, delta line replaced by “Upload a statement to see this.” No prior period: delta line hidden entirely, never “+0%”. Loading: skeleton block at the amount's exact height (no spinner).
Taps
Card body → full transaction list for the range.
W2 · Daily spend linepulse · builder
Job
Show the shape of spending over the range — spikes, quiet stretches, weekends.
Data
Debit total per bucket, plus the mean. Bucket by range: Today → hourly, week/month → daily, 3 months → weekly, year → monthly. Zero-fill gaps; never skip empty buckets.
Look
Header row: “Daily spend” 600/15 left, mono muted average right (“₹1.4k avg/day”). Chart 96 high, full card width, non-uniform scaling allowed. Area fill accentSoft, line accent, stroke 2.5, rounded joins. No axes, no gridlines, no labels.
States
Fewer than 3 buckets: hide the widget (a two-point line is noise). Empty: hidden. All zeros: flat line at the baseline, average “₹0”.
Taps
None in v1. Do not add a tooltip or scrubber unless the label row can show the read-out.
W3 · Category breakdown listpulse · ledger · builder
Job
Rank categories and make the top one obvious without reading numbers.
Data
Per category in range: total, share of total spend. Sorted descending, top 5, with Uncategorized forced to the bottom regardless of size. Category colour = row index in the series (§1).
Look
Header “By category” 600/15 + accent “See all”. Rows: 10dp dot · name 500/14 · fixed 70–80dp track (h6, r3, card2) with a bar in the category colour scaled to share of the largest row, not of total · right-aligned value. Pulse shows amounts, Ledger shows percentages in muted — the layout is otherwise identical, so build one composable with a value-format flag.
States
Empty: single muted line “Nothing categorised yet.” One category: still render the bar (full width).
Taps
Row → category detail. “See all” → Categories dashboard.
W4 · Uncategorized nudgepulse
Job
Make unnamed money visible where the user will actually see it, and give it a one-tap fix.
Data
Sum and distinct payee count of unmapped transactions in range.
Look
Inline banner inside the category card, accentSoft fill, radius 14, padding 14. help glyph in accent · text 400/13 with the amount and “Uncategorized” bold · accent “Map” label. Not a card, not dismissible.
States
Zero unmapped: the whole banner is absent. Never render a “you're all done” variant.
Taps
Whole banner → Mapping health dashboard.
W5 · In / Out / Net tilesledger · builder
Job
State the period's cash position in three numbers.
Data
Credit total, debit total, and their difference, for the range. Requires trustworthy direction on every parsed row; if direction is unknown for any row, exclude it and note the exclusion in the card rather than guessing.
Look
Three equal tiles, gap 10, radius 18, padding 16. Mono eyebrow IN / OUT / NET, value mono 700/19. IN in pos, OUT in neg, NET in pos or neg by sign, abbreviated (“+₹13.5k”).
States
Empty: three tiles showing ₹0 — the row keeps its shape.
Taps
Tile → filtered transaction list (credits / debits / all).
W6 · In vs out barsledger · builder
Job
Show whether each week earned or burned.
Data
Credit and debit totals per sub-bucket (weeks in a month, months in a year), with labels W1…W4 / Jan….
Look
Title “In vs. out, by week”. Plot 132 high with a 1px baseline; per bucket a pair of bars, gap 5, in pos and neg, width ~14, radius 4 top only, heights scaled to the largest single value across both series. Labels mono 11 muted, centred under each pair.
States
Single bucket: hide. Missing credits: render the out bars alone, do not zero-pad a fake in series.
Taps
Bucket → transaction list for that sub-period.
W7 · Category donut + legendcategory
Job

Data

Look
Above the card, a lede sentence: “Food & Dining is your biggest category at 32% this month.” Card is a row: donut 150 box (r46, stroke 17, first slice starts at 12 o'clock, clockwise, no gaps between slices) with abbreviated total mono 700/19 and “this month” 8sp muted centred inside; legend column right, one row per category — dot · short name 500/13 · muted mono percentage.

W8 · Mapping health heromapping · builder
Job
Score the data quality by value, not row count — one unnamed rent payment matters more than twenty unnamed tea stalls.
Data
Mapped debit value ÷ total debit value in range, as a percentage; plus the total.
Look
Eyebrow “MAPPED THIS MONTH”. Percentage mono 700/40 with muted trailing clause “of ₹38,450 has a name” on the same baseline. Track h10 r5 card2, fill accent. Closing body line explains the payoff (“Every payee you name here is recognised automatically in next month's statement.”).

W9 · Waiting on youmapping
Job
Turn the score into a work queue.
Data
Unmapped payees in range: raw parsed string, occurrence count and last-seen date, total amount. Ordered by amount descending — biggest money first, always.
Look
Title “Waiting on you”. Rows separated by 1px line: help glyph muted · raw string 500/14 (single line, ellipsised — never wrap a raw UPI string) · meta “3 payments · last 26 Aug” · amount mono 600/13 · chevron. Below, a full-width accent button “Name all 3 now”.

W10 · Payee rankingpayees · category · builder
Job
Name the actual recipients, since a category answers “what” but not “who”.

Per mapped payee in range: alias, category, total, transaction count. Descending by total, top 5. Unmapped payees are excluded — they belong to W9.
Look
Two shapes, same row grammar: on the Payees dashboard, avatar · alias with a full-width inline track (h5) underneath scaled to the top payee · amount. On the Categories dashboard, avatar · alias with a muted count subtitle (“14 orders”) · amount, no bar. Header carries an accent “All payees” link.

Empty: muted “No named payees in this period yet.”
Taps
Row → payee detail. Link → payee directory.

Credit-direction payees in range: alias, amount, date or frequency meta.
Look
Same row as W10 with the amount in pos and a date/frequency subtitle. Usually 1–3 rows; no bars.
States
Empty: hide the card (a zero-income month is normal, not an error).

W12 · Budget progressbudget · builder
Job
Compare intent to reality per category.
Data
New persistence required: a monthly limit per category. Per row: category, limit, spent in range. Hero: total spent vs total limit, and the count of categories over.
Look
Hero card: eyebrow “PLANNED VS ACTUAL”, mono 700/26 summary (“₹37.6k of ₹36k”), then a neg-coloured sentence naming what is over. Rows: category 500/14 · spent mono 600/13 · limit mono 400/11 muted; track h7 r4 filled accent under budget, neg when over, clamped at 100%; right-aligned note (“₹2,320 over” in neg / “₹1,590 left” in muted).

W13 · Recurringrecurring · builder
Job
Surface the committed, predictable part of the month — the amount already spoken for.
Data
Detection pass over history, not user input: per payee, cluster payments by amount and day-of-month across months; keep clusters present in ≥3 of the last 6 months. Emit alias, typical amount, cadence, next expected date, and a confidence string (“11 of 12 months · 1 UPI ID”) — the confidence string is required, since detection is a guess and the user must be able to judge it.
Look
Banner card in accentSoft, no border, radius 22: one sentence with the expected total. Then rows: event_repeat glyph · alias 500/14 with cadence · confidence subtitle · right column with amount mono 600/13 above muted next date.
States
Under 3 months of history: hide the dashboard and explain in the gallery (“needs a few months of statements”). No clusters found: hide.
Taps
Row → payee detail. Row action → “not recurring”, which suppresses that cluster permanently.

Current dashboard name, selected range, unmapped count (for the badge, if used).
Look

5 · Formatting rules

Currency
₹ prefix, no space, Indian grouping (en-IN): ₹38,450 · ₹1,20,000. Never show paise on dashboards; round to the rupee. Reuse the repo's existing formatter (core/presentation/Formatters) rather than adding one.
Abbreviation
Only where space forces it (KPI tiles, donut centre, averages): ₹1.4k, ₹38.4k, ₹1.2L. One decimal, and never in a hero number or a list row.
Signs
Spend figures are unsigned — the label carries the direction. Net and deltas are signed. Direction arrows ↑ ↓ only on deltas, coloured neg/pos by meaning (up-spend is negative), never by raw sign.
Percentages
Whole numbers, trailing %. Under 1% renders “<1%”, not 0%.
Dates
“26 Aug” · “1–26 Aug” · “Jul 2026”. Always mono. No weekday names outside chart axes.
Raw payee strings
Shown verbatim, uppercase as parsed, single line with ellipsis. Never title-cased or cleaned for display — the user recognises them by their exact form.
Colour meaning
pos = money in or under budget. neg = money out only in comparative context (deltas, overspend) — a plain spend amount uses text colour, or the whole screen turns red.

7 · Open decisions

Answer these before implementation; each changes the data layer, not just the UI.

1
Which variant ships — A, B or C? Everything else in this document is variant-neutral.
2
Does every parsed transaction carry a reliable credit/debit direction today? W5, W6 and W11 depend on it.
3
Where do budget limits live — a new table, or preferences? Monthly only, or per range?
4
Is recurring detection a background pass with cached results, or computed on read?
5
Are dashboard preferences device-local or synced with the account?
6
Do ranges span statements from multiple sources, and what happens when two statements overlap the same days — is the duplicate handling from session detail applied at query time?
